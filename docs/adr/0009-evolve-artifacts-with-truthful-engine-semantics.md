# Evolve artifacts through strict schemas and truthful engine profiles

A0 Self-Improvement will introduce a strict, tagged vNext artifact family, keep behavioral content separate from candidate, lifecycle, generation, and evidence records, and identify every analysis or generation engine by immutable semantics rather than a library or class name. Frozen legacy readers will preserve inspectability and may safe-project the exact valid active `guidance.v1` set as one compatibility incumbent, but legacy readability never upgrades authority. This favors deterministic compatibility, honest provenance, and fail-closed evolution over extending ambiguous records, silent coercion, and relabeling surrogate metrics as outcomes.

## Consequences

- Every vNext Improvement Artifact uses the exact `a0.improvement-artifact.v1` envelope and one strict payload schema. Initial payload schemas are `a0.null-artifact.v1`, `a0.structured-guidance.v2`, `a0.prompt-patch.v1`, and the migration-only `a0.compatibility-guidance-set.v1`. Improvement Candidates use a separate `a0.improvement-candidate.v1` contract. Unknown schemas, versions, fields, or enum values fail closed.
- An artifact contains immutable behavioral content and compatibility identity only. Context activation state, candidate state, timestamps, expiry, activation mode, engine provenance, source findings, validation, replay, scores, and canary decisions do not belong to a vNext artifact. Candidate and evidence freshness remain the separate authorities established by ADR 0004. Frozen legacy fields retain only their exact compatibility meaning.
- The envelope binds the exact Artifact Slot, payload schema, canonicalization contract, artifact digest, and context-, purpose-, and key-epoch-scoped Opaque Reference. Digests are schema-domain-separated over exact canonical bytes and verified on every read but are not public cross-context identifiers. An existing artifact identity with different canonical bytes is an integrity failure; append operations compare equivalence and never hide collisions with `INSERT OR IGNORE`.
- The permanent system-owned Null Guidance Artifact and Null Prompt Patch Artifact occupy their respective Genesis Activation Profile slots. They have fixed no-effect semantics, no engine, evidence, expiry, or promotable state. No guidance is never an absent pointer, empty rule list, empty `guidance.v1`, magic version, or mutable baseline row.
- An Improvement Candidate has exactly one Candidate Change Kind: `replace_structured_guidance` or `replace_prompt_patch`. That discriminator must agree with the target Artifact Slot and proposed artifact schema. It does not encode the optimizer. Null Artifacts, compatibility projections, migration seeds, and legacy rows are never candidates.
- A Structured Guidance Artifact contains only a canonical ordered rule set with strictly typed parameters plus exact Guidance Rule Catalog and renderer-contract references. The existing four-rule maximum remains a structural safety boundary for `a0.structured-guidance.v2`; changing it requires a new compatible catalog/schema decision rather than a mutable threshold.
- A Prompt Patch Artifact contains one atomic set of replacements bound to an exact Prompt Component Inventory, assembly contract, base digest, component identities, source digests, replacement digests, and protected-inventory identity. It may replace only certified eligible components. Whole assembled-prompt replacement, protected components, missing components, reordered inventory, or source drift is incompatible and leaves the original prompt unchanged. Replacement content is durable validated artifact content but is never exposed by public projections.
- Candidate identity binds the artifact reference, exact target slot, incumbent Activation Profile, observed Activation Scope revision, proposed successor profile, Candidate Benefit Claim, Candidate Risk Tier, and Artifact Generation Receipt. Artifact Generation Receipts bind the Engine Profile, admitted analysis or manifest inputs, Model Use Grant when applicable, Worker Dependency Profile, budget and terminal receipt. Evidence Bundles separately bind replay and evaluation authority; arbitrary `validation` or `provenance` maps are forbidden.
- Exact readers return an Artifact Read Disposition of `decoded`, `unsupported`, `invalid`, or `quarantined`. Corruption never collapses into absence or a Null Artifact. Compatibility reads are pure and never migrate, initialize Genesis, change an active pointer, or write caches. New writers never dual-write legacy formats, and older runtimes reject vNext state rather than partially applying it.
- Migration remains operator-initiated and copy-on-write under ADR 0003. The migration snapshots all active guidance pointers and may build one immutable Compatibility Guidance Set from exact schema-valid, digest-valid, scope-valid, nonexpired `guidance.v1` artifacts using their frozen selector and renderer. Embedded `status="promoted"` is ignored as lifecycle authority; the snapshotted active pointers are the only source of incumbency.
- A Compatibility Guidance Set preserves the legacy per-bucket selection behavior inside one context-wide structured-guidance slot and may seed Genesis or remain an exact rollback ancestor. It cannot be proposed, reevaluated as vNext content, or supply promotion evidence. A legacy `engine.kind=heuristic` maps only to deterministic rule projection, while `engine.kind=gepa` maps only to legacy rule-agreement GEPA. Unknown engines, free-form rows, invalid or expired artifacts, digest or scope mismatches, inactive candidates, and in-flight legacy canaries remain quarantined or unsupported; the slot receives Null Guidance when no compatible active set exists.
- Existing unversioned prompt snapshots and prompt artifacts remain readable only through a frozen quarantine decoder and safe metadata projection. Their raw prompt bodies, arbitrary provenance, mutable activation state, and unchecked digests cannot seed Genesis or resume a canary. An explicit release and reevaluation workflow must regenerate the current Prompt Component Inventory and produce a new `a0.prompt-patch.v1` artifact, candidate, and evidence chain. Genesis otherwise uses Null Prompt Patch.
- `a0.guidance-rule-catalog.v1` owns stable rule identifiers, parameter schemas, fixed renderer contracts, allowed benefit buckets, required evaluation buckets, and protected constraints. A structured-guidance Candidate Benefit Claim is eligible only when its bucket is in every selected rule's allowed-benefit set; required coverage is the union of every rule's evaluation buckets plus slot-, risk-, and policy-required buckets. Unknown catalogs, rules, buckets, parameters, or combinations are incompatible.
- The conservative initial rule mapping permits `verify_tool_contract`, `check_tool_result`, `retry_after_failure`, and `bound_tool_scope` for `shell` and `tool_retrieval`; `prefer_reversible_action` is permitted for `shell` and `decision_making`. No current rule is eligible for a `reasoning` benefit claim. Proposed rule names gain no authority until their typed parameters, fixed renderer, affected buckets, deterministic validators, and protected constraints are added through a new catalog version.
- Prompt patches affect the assembled prompt globally, so their initial required deterministic coverage is all four validator buckets: `shell`, `tool_retrieval`, `reasoning`, and `decision_making`. A later certified component-effect profile may narrow this requirement; keyword inference, historical bucket tags, or a generator's claim cannot.
- Each Engine Profile binds a stable semantic engine identifier, output artifact type, analysis route where applicable, optimization objective, Optimization Metric Profile, authority ceiling, adapter contract, exact implementation identity, and Worker Dependency Profile. A semantic change creates a new identifier; dependency, model, or implementation changes create new exact profiles without silently changing the identifier's meaning.
- Initial stable semantic identifiers are `a0.analysis.deterministic.aggregate.v1`, `a0.analysis.typed_predict.v1`, `a0.analysis.recursive_rlm.v1`, `a0.generate.guidance.deterministic_rules.v1`, `a0.generate.guidance.legacy_rule_agreement_gepa.v1`, `a0.generate.prompt_patch.legacy_output_similarity_gepa.v1`, `a0.generate.guidance.outcome_gepa.v1`, and `a0.generate.prompt_patch.outcome_gepa.v1`. Bare labels such as `heuristic`, `gepa`, `Predict`, `RLM`, or `prompt_gepa` are compatibility inputs, never semantic identities.
- Deterministic aggregate analysis may own factual typed reductions. Typed Predict and recursive RLM have proposal-only authority. Deterministic guidance projection may generate a candidate subject to policy and evidence. Legacy rule-agreement GEPA and legacy output-similarity GEPA are diagnostic-only and cannot emit a promotion-eligible candidate. Outcome GEPA may generate a candidate only with a passing GEPA Admission Receipt; its search score still has no activation authority.
- Current rule-label agreement is named `a0.metric.legacy.rule_label_jaccard.v1`, prompt token overlap is `a0.telemetry.legacy.output_token_jaccard.v1`, lexical sequence matching is `a0.telemetry.objective_response.sequence_matcher.v1`, and the current artifact-bound historical-output replay is `a0.replay.legacy.artifact_bound_frozen_output.v1`. Each is Search Telemetry with `promotion_authority=none`; none may be projected as semantic quality, Outcome Evidence, a Validation Result, expected truth, or an outcome-optimized label.
- Search Telemetry stays separate by method. A semantic-judge value never overwrites a lexical field while retaining a lexical method label. Outcome-aligned GEPA's bounded metric and fixed feedback remain search-only even when their admitted replay inputs are derived from typed outcomes.
- Promotion provenance binds the exact Replay Set Manifest, fixture admissions and families, incumbent and candidate profiles, scope revision, Evaluation Envelope, replay adapter and capability certificate, Worker Dependency Profile, budget, model and transport identities, validator identities, Expected Outcome Contracts, Replay Arm Outcomes, cleanup, and opaque case references. Identity-bearing provenance is canonical and digest-covered; non-authoritative annotations occupy a separate namespace and cannot overwrite fixed identities.
- Acceptance separately proves golden serialization and strict decoding; digest tampering and identity collision rejection; Null Artifact behavior; valid active `guidance.v1` projection and every quarantine disposition; prompt release and reevaluation; zero write-on-read; candidate-slot compatibility; rule/bucket coverage; truthful engine and telemetry labels; prompt inventory/protected-component drift; provenance-link integrity; interrupted migration and atomic cutover; standalone source behavior; clean pinned Agent Zero compatibility; authorized provider behavior; and the exact named live runtime.

## Evidence basis

- `guidance.v1` strictly validates its digest but embeds promotion state, expiry, ambiguous engine labels, and nonempty rules, so it cannot represent a Null Artifact: `helpers/guidance.py`.
- The existing Prompt Artifact has no schema discriminator, accepts arbitrary validation and provenance mappings, and does not verify its stored artifact digest during reads: `helpers/prompt_artifacts.py`.
- Prompt snapshot and artifact identifiers omit required scope or contract inputs, while append paths use `INSERT OR IGNORE` without equivalence checks: `helpers/prompt_artifacts.py`, `helpers/engines/prompt_gepa.py`, and `helpers/store.py`.
- Current guidance GEPA optimizes rule-label agreement and current prompt GEPA optimizes token overlap with historical output; neither is outcome-aligned: `helpers/engines/gepa.py` and `helpers/engines/prompt_gepa.py`.
- The accepted profile, privacy, evidence, fixture, replay, activation, and optimization authority boundaries are defined by ADRs 0001 through 0008.
