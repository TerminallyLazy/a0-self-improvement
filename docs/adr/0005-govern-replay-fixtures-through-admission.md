# Govern replay fixtures through admitted immutable artifacts and revocable eligibility

A0 Self-Improvement will admit immutable, typed Replay Case Artifacts through append-only authority and review receipts rather than convert runtime traces or arbitrary case dictionaries directly into replay fixtures. Cases are grouped into stable Fixture Families and selected through immutable Replay Set Manifests whose training, tuning, and Certification Holdout assignments occur at family level. Fixture content, admission authority, eligibility, partitioning, and evaluation results remain separate records. This favors privacy, leakage resistance, and reproducible provenance over automatic harvesting and permanent fixture availability, accepting that consent withdrawal can make historical evaluations non-replayable.

## Consequences

- Admissible origins are signed system-curated regressions, operator-authored cases with attestation, deterministic templates, revision-pinned licensed/public sources, independently reviewed model-proposed drafts, and reviewed Released Fixtures. Runtime observations may create metadata-only drafts but never replay-ready content or expected truth automatically.
- Every non-system content-bearing fixture requires a scoped, expiring Fixture Use Grant that names its purpose and processing boundary. Quarantine-derived content additionally requires its Quarantine Release Grant and a separately reviewed Released Fixture; quarantine is never a fixture library.
- A Replay Case Artifact contains only strictly typed, reviewed fixture content: input message, initial state, ordered Tool Fixture Steps, Expected Outcome Contract, citation facts, state assertions, rubric reference, objective bucket, protected-risk classification, and bounded execution limits. Lifecycle, consent, reviewer identity, and mutable status do not belong to the artifact.
- Tool fixture v1 is a strict linear protocol using an ordinal, allowlisted tool-contract version, fixed exact or typed-schema argument matcher, inert response artifact, and expected state-transition reference. Arbitrary callbacks, executable or fuzzy matchers, live dispatch, credentials, and unreviewed text are prohibited.
- Core safety, policy, schema, and execution truth is system-owned and cannot be inverted by fixture authors. Historical model output is evaluation evidence, never expected truth. Adversarial cases require enhanced review, remain protected data, and cannot enter candidate-generation prompts.
- Each exact artifact requires a Fixture Admission Receipt covering origin/source revision, license or grant, transformation/redaction and scan policies, truth authority, human review, family assignment, partition, eligibility, and processing boundary. Content changes create a new artifact; authority or review changes create a new receipt.
- Exact duplicates are rejected. Variants, translations, generated derivatives, and shared-source cases join one append-only Fixture Family. Suspected semantic siblings require review; families are never split after partition exposure.
- A versioned deterministic policy assigns whole families to training, tuning, or Certification Holdout. Candidate generation sees training only; bounded selection may use tuning; holdout content remains unavailable until the candidate is locked. Public or model-exposed cases carry contamination state and cannot be the sole promotion authority.
- Replay Set Manifests bind exact admitted case versions and receipts, family partitions, ordered selection, coverage, split policy, Assessment Profile, and authority-bearing provenance. Identical incumbent and candidate arms use the same manifest, fixture state, budgets, Execution Profile, and Assessment Profile.
- Fixture Eligibility Events append admission, suspension, expiry, revocation, supersession, or retirement. System-authored safe fixtures may remain until superseded; licensed and consent-derived fixtures cannot outlive their source authority or grant. Mutable and time-sensitive sources create new versions and carry review/freshness deadlines. No universal numerical retention default is established here.
- Withdrawal blocks future replay, invalidates dependent manifests, and makes dependent Evidence Bundles stale. Released payloads are deleted unless another authority independently permits retention; content-free receipts and dependency tombstones remain. Historical evaluation stays auditable but truthfully non-replayable, and active rollback timing remains activation-policy authority.
- Reproducibility means envelope-bound re-execution with comparable typed outcomes, not guaranteed byte-identical model text. Durable data is limited to admitted safe fixtures, receipts, eligibility events, manifests, typed Outcome Evidence and Validation Results, ordered tool/state references, Opaque References, efficiency evidence, and provenance. Raw prompts, arm outputs, tool arguments/results, judge reasoning, and exceptions remain transient.
- Public projections expose only safe origin-class and eligibility counts, manifest opaque identity and coverage, freshness, deterministic/judge availability, and fixed ineligibility reason codes. They never expose fixture content, consent details, reviewer identity, quarantine references, content digests, source locations, or model output.
